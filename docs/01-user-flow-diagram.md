# 01-user-flow-diagram.md (사용자 흐름도)

이 문서는 사용자 목표 달성 흐름을 정의합니다. 본 문서의 흐름은 `06-api-endpoints.md`의 정책과 일치해야 합니다.

---

## 공통 규칙

- 로그인 필요 기능 접근 시 `GET /login?next={원래경로}`로 이동합니다.
- 로그인 성공 시 `next`가 유효하면 해당 경로로, 없으면 `/`로 이동합니다.
- 모든 쓰기 요청 실패 시 사용자에게 원인과 재시도 가능 여부를 명확히 안내합니다.

---

## 1. 사용자가 새 글을 작성하고 발행하는 흐름

- 목표: 로그인 사용자가 개인 글을 작성해 발행한다.
- 행위자: 로그인 사용자
- 시작 조건: 사용자가 웹사이트에 접속해 있다.

### 정상 흐름

1. 사용자가 '새 글 작성' 버튼을 클릭한다.
2. 시스템은 로그인 상태를 확인한다.
3. 비로그인 상태면 `/login?next=/write`로 리디렉션한다.
4. 로그인 사용자는 `/write`로 이동한다.
5. 사용자는 제목/본문(마크다운)을 입력한다.
6. 사용자가 '발행하기'를 클릭한다.
7. 클라이언트는 입력 유효성(빈 제목/본문, 길이 제한)을 검사한다.
8. 서버는 `POST /api/articles`를 처리하고 `type=USER`, `authorId=세션 사용자`로 저장한다.
9. 성공 시 `/blog/{newArticleId}`로 이동한다.
10. 상단 토스트로 '발행 완료'를 표시한다.

### 예외 흐름

- 401: 세션 만료. `/login?next=/write`로 이동.
- 422: 유효성 실패. 폼 필드별 오류 표시.
- 429: 과도한 요청. 잠시 후 재시도 안내.
- 500: 일시적 오류. 재시도 버튼과 문의 안내 표시.

## 2. AI 아티클에 댓글(토론)을 다는 흐름

- 목표: 사용자가 AI 아티클을 읽고 토론 댓글을 남긴다.
- 행위자: 모든 사용자(읽기), 로그인 사용자(쓰기)
- 시작 조건: 사용자가 `/pedia` 또는 `/pedia/{id}`에 진입했다.

### 정상 흐름

1. 사용자가 `/pedia` 목록에서 아티클을 선택한다.
2. 시스템은 `/pedia/{articleId}` 상세를 렌더링한다.
3. 사용자는 본문을 읽고 댓글 영역으로 이동한다.
4. 비로그인 사용자는 읽기 전용 댓글 목록만 본다.
5. 로그인 사용자는 댓글 입력창에 내용을 입력한다.
6. 사용자가 '댓글 등록'을 클릭한다.
7. 클라이언트는 Optimistic UI로 임시 댓글(`status=pending`)을 즉시 목록 상단에 렌더링한다.
8. 서버는 `POST /api/articles/{id}/comments`로 댓글을 저장한다.
9. 성공 시 임시 댓글을 실제 댓글 데이터로 치환하고 입력창을 비운다.

### 예외 흐름

- 401: 댓글 입력 UI를 잠그고 로그인 유도 CTA 표시.
- 404: 대상 글이 없으면 임시 댓글 제거 후 '존재하지 않는 글' 안내.
- 422: 내용 길이/금칙어 위반. 임시 댓글 제거 후 필드 오류 표시.
- 500: 임시 댓글 제거 후 '등록 실패' 토스트 및 재시도 버튼 제공.
